# 端到端案例：匈牙利虚构智能手表上市与测试

## 复现

```bash
python prototypes/2c_gtm/make_demo.py
python prototypes/2c_gtm/server.py --export prototypes/2c_gtm/demo-output
python prototypes/2c_gtm/server.py
```

选择 HU / NOVA-W1 / online，默认运动场景。

| 步骤 | 输入、计算和决策 |
|---|---|
| 发现机会 | 三周动销 46、48、50 台，基线 48 台/周；2026-10-04 期末可售库存 86 台 |
| 选择人群 | HU 有运动/通勤/送礼三组虚构 cells，总权重 39,000；采样 120 人，运动权重 12,000 |
| 匹配证据 | 同 row、sport、google_search 的模拟 RCT：处理 400/5000，对照 200/5000；差 4pp，优化采用 95% 区间下界 |
| 经营约束 | 5 天后到货 80 台；到货前基础需求约 34.29 台，保守增量容量 51.71 台；退货 2/50=4%，贡献 €58.94/台 |
| 4P | 保留手表选品；维持售价并将价格测试独立；提前补货；运动内容与搜索代理人群小额测试 |
| 预算 | 默认区域 €5,000 场景下此单元投入 €850；曲线预测增量 42.27 台，小于库存容量；此数字是假设曲线结果 |
| 验证 | 独立后测包含模拟动销、退货、库存和扣营销后的贡献；即使动销提升，也不能无对照归因 |

在界面把运动改为送礼：同一输入合同不变，但你选择了另一种人群/动作假设，因此现有 sport 实验不能迁移。系统重新评分并降到“假设级”，每单元投入上限为 €300。JSON 导出包含完整证据、经营约束与动作。

再选择 GR / NOVA-W1 / online：期末仅 21 台，周均需求 58 台，到货晚于一周，增量容量为零，预算为零。选择 RO / NOVA-T1：退货率约 13.11%，优惠后贡献为负，先排查产品体验与服务。

默认总体投入 €3,700，保留 €1,300；10 个阻塞单元为 €0。总预测利润是虚构响应曲线的情景输出，不是因果验证或真实经营收益。
